AUTOKART RC  |  EXECUTIVE SUMMARY

Executive Summary

Engineering status as of 28 September 2026

After the 02 September baseline, the project added direct IMU and encoder tests, a two-controller RS485 link, LoRa emergency-stop prototypes, revised BLDC transistor pin assignments, a 5 V traction-command test, and a NEMA 34/R86mini steering bench program.

Confirmed progress
The ESP32-S3 traction bench controller runs with BRK on GPIO13, EN on GPIO14, F/R on GPIO15, and a GP8630N limit of 5.00 V. Steering is smooth with the kart jacked or at low pulse rates. The LoRa transmitter and standalone receiver tests can exchange explicit ESTOP,0 and ESTOP,1 packets.
Primary unresolved issues
Steering still stutters or slips under tyre load and begins to lose smoothness around 600-800 pulses/s in the recorded test. BLDC speed remains strongly asymmetric: counter-clockwise runs at substantially higher RPM than clockwise for the same requested voltage. The combined LoRa/BLDC implementation is not yet the default controller and still needs an end-to-end validation pass.

Key findings after 02 September

  • Direct MPU-9250/6500 detection required NCS held HIGH and the tested SDA/SCL wiring moved to GPIO11/GPIO12.
  • RS485 communication worked after direction control and packet framing were corrected; early logs showed fragmented and corrupted packets.
  • The remote LAY37 E-stop was kept electrically separate from actuator GPIO. Its state is transmitted by LoRa from the Pico 2 side.
  • BLDC EN and BRK pins were swapped in firmware to match the transistor wiring: BRK GPIO13, EN GPIO14.
  • The throttle ceiling changed from 3.00 V to 5.00 V, producing a significant RPM increase.
  • The web slider changed from 0.05 V to 0.01 V steps and request coalescing was added to prevent an unresponsive UI.
  • AS5600 I2C, AS5047P SPI/PWM, and brake-feedback calibration utilities were added as isolated tests.
  • NEMA 34 + Rtelligent R86mini testing was added on 28 September with a conservative ramp and +/-20 degree limits.

Isolated LoRa emergency-stop path

  Handheld / remote side                         Vehicle bench side

  3.3 V -- 4.7 kOhm --+                         +-------------------+

  GND -- LAY37 COM/NC -+       |                 | LoRa receiver     |

The switch is electrically isolated from actuator-control GPIO: the only connection between remote and vehicle sides is the LoRa radio link. This reduces long emergency-switch wiring and prevents the handheld switch circuit from sharing actuator signal wires.

Integration limitation: The current ESP32 RA-02 bench mapping uses GPIO4/5/6 and GPIO10. Those pins overlap steering and brake controls. It is valid for the BLDC-only LoRa bench test, but it is not a conflict-free full-vehicle pinout.

Communication & Sensor Test Circuits

ESP32-C3 to ESP32-S3 RS485 bench link

 XIAO ESP32-C3                 CAT5e twisted pair                  ESP32-S3

 GPIO21 TX -> MAX3485 RX     A ============================== A   MAX3485 RX <- GPIO17 TX
 GPIO20 RX <- MAX3485 TX     B ============================== B   MAX3485 TX -> GPIO18 RX
 GPIO10    -> MAX3485 EN     GND/reference ---------------- GND   MAX3485 EN <- GPIO16

 Direction: EN HIGH = transmit; EN LOW = receive
 UART: 9600 baud, 8-N-1
 Test protocol: PING,sequence <-> PONG,sequence

Why these pins: XIAO GPIO20/21 correspond to exposed RX/TX labels; GPIO10 controls transceiver direction. ESP32-S3 GPIO17/18 form a separate UART pair and GPIO16 controls direction. Module labels describe module signal direction, so MCU TX connects to module RX/RXO.

Standalone encoder connections

Signal requirements

  • Use a diametrically magnetized magnet centered over the encoder IC.
  • AS5600 raw 0-4095 maps to 0-360 degrees.
  • AS5047P SPI provides 14-bit angle; PWM must be enabled through SETTINGS1.
  • All ESP32-S3 inputs must remain within 3.3 V logic limits.

Message logic change

state = 1 if estop.value() else 0
packet = "ESTOP,{},{}".format(state, sequence)

ESTOP,0,n  -> released / clear red UI
ESTOP,1,n  -> command stop and brake

The first design used a continuous healthy heartbeat and stopped whenever packets were delayed. Bench delays caused false stops. The bench logic changed to explicit stop/clear messages so plugging or unplugging the Pico does not independently raise the red screen. This is diagnostic behavior, not fail-safe radio-loss behavior.

Safety trade-off

Explicit-message E-stop mode prevents false red-screen activation when the remote is unplugged, as requested for bench testing. It also means radio loss alone does not command a stop. A vehicle design must distinguish STOP, CLEAR, stale sequence, corrupted packets and lost communication, with an independent hardware stop path.

Why the stable BLDC file was restored

Commit 4abfe30 removed the partial LoRa merge from full_bldc_test.py. This preserved known-working traction behavior while retaining LoRa work in separate files.

Diagnostic principle: isolate one interface, verify identity or signal edges, then integrate. Serial access proves MCU communication only; it does not prove the radio, sensor, actuator or mechanical load.
