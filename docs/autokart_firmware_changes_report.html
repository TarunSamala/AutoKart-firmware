AutoKart Firmware Bench Report

Changes, troubleshooting history, and pinout comparison — 21 September 2026
Scope: This report covers the firmware and bench wiring developed in AutoKart-firmware for ESP32-S3 BLDC testing, steering/brake tests, and RA-02 LoRa emergency-stop experiments. It is a bench record, not a road-ready safety certification.

2. Changes made

  • Repository organization: bench MicroPython tests are under bench/, vehicle firmware under firmware/, wiring notes under docs/, and board images under images/.
  • BLDC transistor mapping: BRK and EN were exchanged so the active controller uses BRK GPIO13, EN GPIO14, and F/R GPIO15. F/R stayed on GPIO15.
  • Throttle range: the BLDC bench file was changed from a 3 V test range to a 5 V maximum. The slider was changed to 0.01 V resolution and its request handling was made smoother by sending the latest pending value instead of flooding the web server.
  • Direction test: clockwise and counter-clockwise output were compared. The large difference observed in one direction was recorded as an engineering issue to investigate, not treated as proof that the command voltage was wrong.
  • LoRa pin conflict avoidance: the ESP32-S3 RA-02 test uses GPIO4/5/6 for SPI and GPIO7 for CS, leaving GPIO13/14/15 available for the BLDC control transistors.
  • E-stop message logic: the Pico transmitter sends ESTOP,0,sequence at startup/release and ESTOP,1,sequence while the LAY37 is pressed/open. The full non-LoRa BLDC file was restored as the default bench controller; LoRa integration remains in its own file.
  • Steering test: steering and brake pulse outputs were separated onto GPIO4–6 and GPIO10–12. Steering is represented as a 90° software window centered at 0°.

6. Errors and issues encountered

Observed issueCause / interpretationResolution or lesson
mpremote: failed to access ... may be in useThonny, a REPL, or another Python process owned the serial device.Close the serial monitor, then check lsof /dev/ttyACM0 or lsof /dev/ttyUSB0 before reconnecting.
could not enter raw repl, b''The board was busy running code, the port was locked, or the image/board state was not suitable for raw REPL.Reset the board, use one serial client at a time, and confirm MicroPython is installed on the correct board.
Wrong or missing serial portACM/USB names are assigned dynamically; bootloader mode can appear as a mass-storage device instead of a serial port.Rediscover the port after reconnecting. Do not assume ACM0, ACM1, or ttyUSB0 is permanent.
MicroPython ImportError: no module named 'network'Code intended for ESP32 was run on a board/image without the expected ESP32 networking module, or the wrong device was selected.Match the firmware and script to the board; keep ESP32 and Pico files separate.
RP2 bootloader had no /dev/ttyACM*Pico 2 was still in RP2 UF2 bootloader mass-storage mode.Copy the UF2, allow the board to reboot, then look for the new serial device.
RA-02 packets not initially seenRadio pin mapping, serial-port selection, one-shot timing, and receiver state were being tested simultaneously.Use the standalone receiver/transmitter tests first and verify SX1278 version 0x12 and explicit packets.
Integrated LoRa test stopped with name 'reason' isn't definedA handler/error-path variable was referenced before definition in the combined controller.Keep the stable non-LoRa BLDC controller separate while the integrated file is repaired and retested.
Motor stopped during slow-speed testingControl pin changes, throttle ramp/watchdog behavior, and controller response were being changed during the same test sequence.Stabilize the pin mapping first; test voltage/ramp/direction independently with wheels off the ground.
CW and CCW speed differed substantiallyPotential motor/controller wiring, mechanical load, direction input, or drive-stage asymmetry; not enough evidence to attribute it only to target SV.Measure actual SV in both directions and inspect motor phases, F/R logic, brake release, and mechanical load.

8. Recommended next test

  1. Keep the BLDC controller on bench/full_bldc_test.py and verify BRK/EN/F-R transistor logic at zero target voltage.
  2. Run the Pico transmitter and ESP32 receiver alone; print every received packet before connecting the BLDC control loop.
  3. Test only two E-stop transitions: startup/release packet ESTOP,0, then pressed packet ESTOP,1. Confirm brake application and red UI state.
  4. Only after that, combine radio handling with the controller and test at low target SV, with wheels lifted and a physical power cut available.
