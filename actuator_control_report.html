AutoKart RC — Actuator Control

Compact implementation report • Based on the controller and wiring files in this workspace • 02 September 2026
Primary implementation: autokart_rc_v5_controlled_stop.py. It is an ESP32-S3 Wi‑Fi bench controller with open-loop stepper positioning for steering/brake and an analog throttle command for the BLD750.

Actuator interfaces
TB6600 and GP8630N/BLD750

Steering actuator

Stepper motor through a TB6600 driver. Motion is generated as STEP pulses; DIR selects sign; ENA enables the driver.

Brake actuator

Second stepper/TB6600 axis. Positive motion is configured as clockwise brake application; range is 0 to +15° in v5.

Throttle / traction actuator

ESP32 writes a 16-bit value to the GP8630N over I²C. The module is configured for 0–10 V and its OUT feeds BLD750 SV.

Drive safety inputs

full_bldc_test.py separately demonstrates BLD750 enable, quick-brake and F/R inputs via GPIO13–15 and PN2222A transistors.

3. Steering and brake control

Each axis is represented by a StepperAxis object. The browser sends a target or nudge; the ESP32 clamps it to the configured range, converts degrees to pulses, and the main loop moves one pulse at a time until the software target is reached.

ParameterSteeringBrake
Software range (v5)−90° to +90°0° to +15°
Pulse calibration3200 / 360 × gear ratio pulses per output degree; ratios are currently 1.0.
Pulse timingStarts 1200 µs, ramps to 500 µsStarts 1500 µs, ramps to 700 µs
Motion commands/steer_left, /steer_right, /steer_nudge, /steer_hold, /steer_center.

Important limitation: this is open-loop. The reported position is only the number of commanded pulses from an assumed physical zero; there is no encoder or limit switch feedback. The mechanism must be physically centered/released at the assumed startup position, and the gear ratios must be calibrated.

Actuator Control — Operation & Safety

How commands become actuator motion

4. Throttle control sequence

  1. The UI sends a normalized throttle request; the server clamps it to 0–3.0 V and accepts it only when armed and the brake is released.
  2. The request becomes throttle_target. Every 15 ms, throttle_update() ramps the actual output toward that target.
  3. v5 increases by 0.02 V per update and normally decreases by 0.10 V per update. The voltage is converted to a 16-bit DAC code: int((V / 10) × 65535).
  4. The code is written to GP8630N register 0x02; the GP8630N output controls BLD750 SV.

Bench-only status: the source notes that the BLD750 previously faulted near 0.75 V, so the 3.0 V ceiling is not electrically validated. Keep wheels off the ground until the fault and command scaling are resolved.

5. Brake, arm, stop, and watchdog logic

EventController action
BootThrottle = 0 V; steering target = center; brake target = applied; TB6600 drivers enabled after initialization; controller remains disarmed.
ArmThrottle = 0; steering holds; brake target moves to 0/released; then commands may be accepted.
Brake onImmediately zeros throttle, marks brake active, and targets +15° clockwise application.
Brake offReleases the stepper brake to 0° and forces throttle to zero; a new throttle command is required.
Controlled stopDisarms, ramps throttle down at 0.04 V every 15 ms, then commands full brake application once throttle is near zero.
通信 timeoutIf an armed controller receives no heartbeat for 1.8 s: disarm, throttle zero, steering hold, brake apply.
E-stopLatched state: throttle zero, steering hold, brake apply, all commands blocked until reset; reset leaves the system disarmed.

6. Standalone BLD750 actuator test

full_bldc_test.py is a separate direct-drive bench test. PN2222A transistors pull BLD750 control inputs low when their GPIO is high:

GPIOBLD750 inputFunction
13ENHigh → transistor on → input low → RUN; low → STOP.
14BRKHigh → input low → brake released; low/open → quick brake.
15F/RDirection selection; software labels states CW and CCW.

That test applies a layered safe stop: command the GP8630N to 0 V, apply BLD750 brake, and stop/disable enable. Direction changes are allowed only in the full safe state.

7. Practical validation checklist

  • Confirm TB6600 microstep switches match the assumed 3200 pulses/revolution.
  • Measure actual steering and brake travel; update gear ratios and software limits.
  • Verify DIR polarity and brake apply direction at low speed.
  • Verify GP8630N 0–10 V scaling with a meter before connecting/energizing traction.
  • Test arm interlock, brake/throttle interlock, controlled stop, E-stop, and 1.8 s heartbeat timeout with wheels off the ground.
  • Add physical end stops or feedback before treating the open-loop angle estimate as a safety-critical position.
